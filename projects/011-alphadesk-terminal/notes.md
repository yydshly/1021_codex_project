## 源码核对

- 从 `alphadesk/mcp_server.py` 的装饰器 AST 提取工具参数、默认值、文档与源码行号，运行时再次核对 53 项。上游介绍存在不同旧计数，以固定提交代码为准。

## 原版运行

独立 Python 3.12 环境安装固定提交，使用上游自带构建 UI，未修改上游源码。默认启动器禁止非本机 TCP，关闭 dotenv、采集循环和模型，使用独立数据库；不是通用安全沙箱。

`verify_original.py` 用临时数据库和真实 TestClient 完成 24 项 HTTP 状态断言，另外完成 53 工具注册核对、MCP 握手/列举/两个工具调用/撤销令牌。令牌仅内存使用，不写入报告。记录见 `validation-original.json`，真实运行时 schema 见 `app/runtime-tools.json`。

浏览器实际打开原版 Account/Markets，截图见 `assets/original-account.jpg`、`original-markets.jpg`。新闻、报价、图表等显示需要密钥，国债数据在离线模式不可用，符合当前配置。没有向原版注入样例充当行情。

## 第二阶段：真实公开数据接入

用户选择暂不接入 SEC。新增 `--public` 模式，仅从原版现有 Yahoo、Nasdaq、US Treasury、Federal Register、Federal Reserve 适配器读取数据，不更换成手工响应。SEC 的 `_get` 在此模式明确拒绝调用，即使进程环境存在联系信息也不请求；商业环境凭据仍清除。没有改动上游仓库源码。

实际 HTTP 返回：NVDA 月日 K 23 根、有效报价、国债 12 期限、政府事件 40 条、停牌 39 条、IPO 2 条。`verify_public.py` 还核对真实 MCP 的报价/事件/停牌内容非空并撤销临时令牌，不再只断言协议层成功。报告记录响应哈希，原始响应留在本机忽略目录。

Nasdaq 停牌第一次 HTTP 请求返回 428，但实际原因是排队填充缓存。之后 MCP 读取成功，再查 HTTP 返回 39 条；这是上游冷启动状态表达的局限，不是需要商业密钥。政府 feed 的 Fed RSS 未按 days 参数硬过滤，不能把整张表解释成严格时间窗口。Yahoo 报价没有成交时间；图表响应没有来源字段，通过 capabilities 接口确认提供商。均在说明中保留边界。

分红周查询在 45 秒客户端时限内未完成；源码按天顺序请求且每次可等待 20 秒，因此整周可能阻塞很久。拆股返回缺少来源提示，尚未取得数据。TreasuryDirect 的拍卖接口返回空列表，未解释成无拍卖。未绕过拒绝或伪造响应。

原版 UI 验证：NVDA 1M/Candles 真实绘制；Markets 显示 Yahoo 来源、真实报价和 Treasury 表；Calendars 显示官方规则/公告和 2 条 IPO。通过 Customize board 将 Markets 保存为三个可用模块。截图 `real-chart.jpg`、`real-markets.jpg`、`real-calendars.jpg` 区别于第一阶段无凭据截图。

本机真实终端监听 8782；8781 仍是静态教学界面，新增醒目的真实终端入口与 `real-data.html` 接入说明，不把虚构数据悄悄改成半真半假的混合数据。所有代码与目录校验通过后交付。

## 按信息方向重排架构图

用户反馈上一版系统框和代码名过于抽象，因此当前图改成“上方核心架构 + 下方具体业务链”。先讲四类信息：行情、新闻、公司披露、政策日历；再以第五行说明组合研究不是新数据源。每行列出来源及获取方式、实际转换与计算、展示形式和能力边界。

核心架构只保留人/AI、服务入口、共享研究后端与输出，并将数据库、缓存、后台更新、身份与错误作为共同支撑。真实截图随对应业务行出现；新闻与 SEC 没有本次实跑截图，使用标明性质的功能结构示意。源码复核纠正了一个容易混淆之处：trumpstruth.org 走独立帖子流，不与新闻文章共用股票标签和去重检索表述。

查看器新增四栏分别放大，减少在大图中寻找对应内容的负担；图尺寸更新为 SVG 2800 × 2630、PNG 5600 × 5260。此前验证条目作为历史记录保留，新检查单独记入 validation-research.json。
