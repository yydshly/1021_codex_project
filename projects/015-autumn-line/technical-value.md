# 可沉淀的技术价值与落地路线

## 结论

我们的最终定位是：**自然环境类 3D 场景素材 + 可复用的生成与渲染方法**。它属于自然场景素材库中的一个完整案例，直接价值集中在特定的秋日铁路环境，不扩大为通用三维创作平台。

最大能力：用少量模板和规则，组织出有细节、有统一画风的自然环境。素材以 Three.js 源码和实时场景提供，既有现成可看的世界，也有可以改造的生成规则；不是现成的 GLB/FBX 模型素材包。

## 对我们的具体意义

可以把它当作一处虚拟外景地：搭一次环境，多次取景；修改参数、布局和相机，制作相近自然主题。保留它的意义是积累环境素材与制作方法，在出现自然背景需求时减少重复搭建。第二个主题的制作效率尚未验证，不将潜在收益说成已有结果。

| 应用 | 环境提供什么 | 需要补什么 |
| --- | --- | --- |
| 游戏环境 | 树林、山谷、铁路与统一画风 | 碰撞、角色、玩法与资源管理 |
| 动画 / 短片背景 | 一致的三维空间与可重复取景 | 镜头时间线、高清录制或逐帧导出、音画合成 |
| 分镜预演 | 调整机位与视场，比较构图 | 镜头路径、机位保存、分镜导出 |
| 插画 / 海报背景 | 多角度取景与配色调整 | 静帧输出流程、排版与人物/产品素材 |
| 互动网页 | 可直接托管与嵌入的场景 | 内容热点、业务叙事、目标设备优化 |
| 图形教学 | 程序化建模、卡通材质与渲染诊断 | 具体实验任务和教学内容 |

水体、建筑、人物、室内和工业产品不属于现成场景资产，迁移到这些主题需要补资源。固定镜头背景通常先考虑图片或视频；只有需要改变视角、操作物体或改变环境时，实时三维的额外成本才更容易成立。

## 效果接入分三层

1. **直接展示**：将整个 `web/` 静态托管，链接 `index.html` 或 iframe 嵌入 `scene.html`。无需模型 API，需可运行此场景的浏览器/GPU。保留相对资源路径；研究页的参数通信仅支持同源父子页面。
2. **修改代码复用**：抽取树木、地形、材质与相机逻辑，处理依赖并重新配置布局。不能只更换参考照片就得到新场景。
3. **另行开发工具链**：模型资产导出、视频导出、镜头时间线、可视化编辑器和其他引擎适配。转到 Blender/Unity 等环境需要另做几何与材质转换，原自定义 GLSL 不会自动保留全部效果。

最适合长期沉淀的是自然资产、场景配置、风格渲染、镜头控制；展示生命周期是配套能力。通用照片生成、精确空间重建与游戏玩法不在它的能力内。

本研究已保存源码、制作参数实验页并整理边界。以下接口及产品方向是**建议方案，尚未实现为独立组件或验证商业收益**。

## 1. 风格包：优先提炼

路径：`render/toon.ts`、`render/post.ts`、`render/leafAtlas.ts`。

原理：材质写出两个渲染目标，分别携带颜色/描边权重和法线/深度/对象标识。全屏后处理用邻域差异提取轮廓，按深度衰减远处线条；叶片使用特殊权重，抑制叶片交叠产生的黑线。卡通明暗和轮廓是两个独立阶段，关闭描边不会自动恢复 PBR 写实渲染。

可提炼的配置包括 `palette`、`sunDirection`、`shadowTint`、`fog`、`outlineStrength`、`outlineWidth` 和诊断模式。建议形成 `createStylePipeline(renderer, style)`，约定材质必须输出哪些缓冲信息，并提供 `resize`、`render`、`dispose`。这是接口建议，不是现有 API。

验收方法：先用平面、球、盒子和透明叶片构成最小场景，确认明暗分区、物体交界、轮廓衰减和透明边界都符合预期，再迁移到第二个主题。要确认的是能否脱离“秋日铁路”成立，而不是原场景截图是否漂亮。

本页实验：轮廓诊断 + 强度 0/1 对比；法线/深度视图解释边界来源；风力 0/1/3 观察顶点位移。深度视图按 50 m 重复，不提供真实距离读数。

## 2. 自然资产包：复用度高，但应整理参数

路径：`world/builder.ts`、`trees.ts`、`forest.ts`、`cover.ts`、`core/rng.ts`、`core/ecology.ts`。

树木模板用分支、树冠体积块与叶片卡片组织，随机种子控制外观；森林再决定位置、物种、大小、旋转与颜色。实例化复用几何，并不意味着无需顶点处理、透明片元开销或阴影渲染。

建议拆为三个层次：

1. `PlantSpec`：物种、种子、树高、树冠宽、叶片数量和颜色。
2. `ScatterSpec`：边界、密度、随机种子、禁种区及地面高度查询。
3. `RenderBudget`：近中远模板预算、实例分区、可见性与销毁。

生成过程应返回数据和可管理的资源，不把整个世界绑在全局常量上。模板缓存可以减少重复构建；需要明确共享纹理、材质与几何的所有权，避免重复销毁。

验收方法：同一种子重复生成布局一致；禁种区域不出现植物；所有实例落在地表；第二套颜色能切换到另一个季节。动态 LOD、相机附近重新生成或流式载入都属于新增能力，当前源码未实现。

## 3. 场景布局：沉淀方法，不照搬坐标

路径：`core/layout.ts`、`world/track.ts`、`terrain.ts`。

轨道纵向位置与横向偏移建立一套空间基准，地形贴合路基，植被依据铁路距离避让。照片中影响轮廓的重要树木明确布置，外围使用规则填充。这种做法可迁移到河流、步道、街道等有明确主线的场景。

应保留的思路：先确定主视角与主要形状，再布置重要物体，最后填充变化。需要重新设计的内容：相机视场、道路曲线、山丘、日照、树冠层次。照片没有提供完整空间信息，背面区域与尺寸由场景作者设计，不能当作测绘数据。

建议将 `CameraPreset`、`PathSpec`、`TerrainSpec`、`HeroPlant[]`、`Palette` 组合成可保存的 `ScenePreset`。可以先做“铁路秋景 / 河岸夏景”两个案例，验证是否真正摆脱特定坐标耦合。

## 4. 展示外壳：本次已有可复用实践

本地新增 `src/research.ts`、`src/boot.ts`，并在 `main.ts` 增加有限消息协议。入口页面不加载 Three.js 场景模块，点击后才创建 iframe 场景；失败时保留可读提示和释放入口，研究内容仍可阅读。

参数消息仅接受同源、指定父窗口、指定 channel、白名单动作和范围内数值。包含相机模式、描边、风、诊断、精度、暂停与可见状态；不会接受任意脚本或任意属性赋值。父页展示真实生成耗时、实时帧率和错误状态。释放 iframe 退出场景上下文；`pagehide` 同时处理主要几何、材质、渲染目标与 renderer 的销毁。

仍需完善：完整资源所有权模型、独立场景页的触屏移动与暂停控件、无 WebGL 的跨设备验证、长时重复加载的显存观察、上下文恢复、屏幕阅读器的三维内容替代描述。不能把一次页面验证等同于生产可用性认证。

## 应用选择

| 场景 | 值得投入的条件 | 需要新增 | 验证指标 |
| --- | --- | --- | --- |
| 品牌/活动交互展示 | 用户能点击场景热点、改变视角，三维参与叙事 | 热点、内容、品牌风格、低配降级 | 到达主要内容时间、交互完成率、目标设备帧率 |
| 专注环境 | 空间氛围能产生持续使用理由 | 环境音、设置、场景切换 | 使用时长、重复使用、耗电与发热 |
| 独立游戏原型 | 需要快速确认环境风格与行走感 | 碰撞、角色、玩法、资源管理 | 完成具体玩法任务、穿模率、资源预算 |
| 固定背景 | 无需交互或改变镜头 | 通常改为图片/视频 | 总加载成本和视觉一致性 |
| 照片转世界 | 需要处理任意输入 | 另建重建/生成系统，不能只改 UI | 几何质量、跨视角一致性、成功率 |

没有用户研究或商业试验支持收入、转化提升或留存提升的结论；这些方向属于研究判断。

## 建议执行顺序

1. 风格管线解耦与第二场景复用验证。
2. 植被和布局配置化，明确资源所有权。
3. 针对目标设备做性能预算：加载、几何、绘制调用、阴影、像素比与显存。
4. 选择一个有交互需求的业务原型，验证三维是否带来可观察的使用收益。

暂不扩展为通用编辑器或 AI 生成平台。当前研究项目已覆盖第一步之前的代码保存、技术理解与参数观察。
