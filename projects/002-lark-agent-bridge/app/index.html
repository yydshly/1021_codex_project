LARK CODING AGENT BRIDGE 开源 · MIT

让聊天，
成为工作的入口。

把飞书消息接入本地 Claude Code / Codex，让 Agent 读取项目、修改文件、运行工具，并把执行过程与结果送回聊天。

本质是适配器配合 Agent 对外提供的执行接口：
Bridge 组织会话与运行，Agent 提供实际执行能力。

03 / THE IMPORTANT DISTINCTION

管理了一次运行，
不等于管理了一个完整任务。

≠

这是本次讨论最关键的认识。理解边界，先把“消息、任务、运行、会话”分开。

MESSAGE

消息

一次输入。用户说了什么、来自哪里。

“修复登录报错。”
TASK

任务

一个目标，包含约束和验收条件。

登录修复，指定测试通过。
RUN

运行

某个 agent 的一次具体执行尝试。

首次执行失败，修正后重试。
SESSION

会话

连续交互的上下文及其标识。

“接着刚才的分析继续。”
3 条消息 → 1 个任务 → 可能有多次运行

“修复登录”＋“只改后端”＋“跑一下测试”可以共同描述一个目标。会话保存上下文，不天然等于一个独立任务。

当前实现与进一步设计

已阅读源码

围绕聊天范围，组织一轮轮运行。

消息合并与等待

同一范围内的消息合并为一批；运行期间的普通新消息等下一轮处理。

会话关联与恢复

匹配聊天范围、agent、目录和权限条件，带着会话 ID 继续执行。

并发限制与中断

同一范围防重复运行，通过运行池控制并发；停止指令交给运行句柄处理。

结束与资源清理

消费结束或错误事件，维护活动运行记录并清理；pending 队列使用内存存储。

这些属于会话与运行管理。仅凭这条核心链路，不能认定已有持久化任务队列、任务依赖和自动验收系统。

!

“正常结束”是执行事实，“任务完成”是验收结论。

Agent 退出成功，仍可能没有修好问题。运行结束后，应通过测试、产物检查或人工判断确认目标是否达成。

04 / THE ADAPTER CONTRACT

适配器负责执行接入，
调度器负责安排工作。

Codex / Claude Code 已提供非交互式 CLI、会话恢复和结构化输出能力。适配器将这些接口接入统一的执行流程，翻译输入、启动进程、归一化输出并处理停止与退出；任务的优先级、依赖和验收策略应放在上层。

EXTENSION / 架构建议

两端可以替换，
能力需要逐项对齐。

换 agent支持非交互式 CLI、SDK 或 API，就具备接入基础。结构化事件方便可靠解析；会话恢复、取消、附件和权限支持决定体验是否完整。

换聊天平台需要双向消息接口，还要匹配身份、附件、回调时限和回复展示。企业微信已有长连接机器人 SDK；个人微信、公众号与企业微信不能视为同一种接口。[7]

扩展当前仓库Agent 侧已有统一接口，但配置、能力声明、会话分支也要接通；消息与卡片仍包含飞书相关逻辑，迁移平台需要相应改造。

外部控制是否意味着，可以随时接管 agent 的每一步？+

这份实现主要提供启动一轮执行、读取事件、恢复会话和停止进程。它没有因此自动获得“任意时刻注入指令”或逐个工具批准的通用能力。运行期间的普通消息会排到下一轮；更细的控制取决于 agent 的接口与 Bridge 的实现。

会话记忆保存在 Bridge 还是 agent？+

在这条 CLI 恢复链路中，历史上下文主要由 agent 维护；Bridge 保存聊天范围与 agent 会话标识、工作目录等信息的对应关系。恢复时传入已有标识。更换 agent 不等于能直接复用另一种 agent 的会话 ID。

使用前要理解的四个边界

01本地执行 ≠ 本地推理CLI 在本机操作，模型请求仍按其配置发送。

02工作目录 ≠ 文件隔离cwd 决定从哪里工作，实际访问范围由权限机制决定。

03会话隔离 ≠ 项目隔离不同聊天可能修改同一目录，并发限额不等于文件互斥。

04默认权限需要看清研究版本新 profile 默认 full，可改为 workspace 或 read-only。
