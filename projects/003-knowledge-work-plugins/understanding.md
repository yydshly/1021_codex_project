# 我们对 Knowledge Work Plugins 的理解

**这是一套给 Claude 使用的插件与 Skill 集合，核心是把岗位经验与业务 SOP 包装成可复用的方法。** 插件负责组织能力，Skill 描述具体任务，Claude 根据请求理解和匹配方法，配合工具完成工作。固定版本的结构与来源见 [证据索引](source-index.json)。

## 能力如何组织与匹配

- **按岗位 / 能力领域组织插件：** 销售、客服、产品、营销、法务、财务、数据、生命科学、设计、研发、人力、运营、小企业经营，以及任务记忆、企业搜索、插件创建、PDF 协作等。
- **按业务场景组织 Skill：** 同一个销售插件包含客户研究、会前准备、商机更新、续约等不同任务；同一个客服插件包含分诊、回复、升级和知识文章等任务。
- **按请求匹配执行：** 用户提出目标后，宿主和模型依据 Skill 的描述及触发条件选择相应方法、读取所需资料、执行适用步骤并交付结果；显式命令也是一种入口。具体加载和工具权限由宿主实现，不能把自然语言的“匹配”当作已验证的确定性调度服务。
- **按实际输入适配：** 公司规则、口径、文件格式、可用工具和缺失材料都会影响流程。岗位名称是使用视角，系统账号和读写权限需要另行配置。

固定快照有 **17 个顶层插件、181 个 Skill、5 个独立 Command 文件**。它们并非 181 个互不重叠业务，也不是 17 个独立训练的岗位模型。全貌见 [能力引导图](assets/capability-map.png)，具体入口见 [角色地图](roles.md) 与 [全量索引](scenario-index.md)。

## 本质为什么仍是工作流

它将“输入什么、按什么步骤做、出现例外怎么办、怎样交付”写成模型可以遵循的业务流程。传统工作流通常用代码和状态机控制分支；Skill 将一部分资料理解、步骤选择、判断与内容生成交给模型。部分插件另附脚本、模板和 MCP 配置，提供实际计算或工具连接路径。

模型可以理解模糊问题和非结构化材料，但遵循提示的稳定性仍需检查。Skill 中的“必须审批”首先是一条文字要求；若要让未批准的操作无法发生，服务端还必须检查身份、对象、版本和状态。详见 [业务控制分析](business-analysis.md)。

## 对我们的意义

1. **作为需求设计参考。** 找相似场景，明确目标、输入、证据、异常、人工决策和验收，帮助把一句模糊需求变成可检查任务。
2. **作为业务 SOP 案例库。** 参考已经拆分的检查点与交付结构，替换成自己的组织规则，减少每次从头设计的工作。
3. **作为高频能力的封装参考。** 对反复使用、规则稳定或多人交接的任务，考虑沉淀为自己的 Skill、模板或工具配置；一次性任务可以直接对话。
4. **作为落地控制的设计参照。** 判断哪些要求交给模型，哪些由脚本复算，哪些必须在业务系统中强制执行，避免把提示词当作权限或审批系统。

预期价值是减少重复交代、遗漏和返工，并统一交付方法。这些尚无量化收益实测。提供同样完整资料、流程和工具的直接对话，也可能得到相近结果；插件包装主要增加加载、触发、复用、配置与维护的便利，不能直接等同于模型更聪明。

## 用工单案例理解，以及本次实际做到了什么

客户说“登录白屏，非常急”。流程先补环境、人数、替代方案，再查关联问题、分级、建议路由与起草回复。生产环境 120/120 人受阻且无替代方案，在演示公司规则下为 P1；测试环境 1/120 人且有替代方案则为 P3。

本研究新增的本地程序真实验证了：缺关键事实时拒绝批准、未批准时拒绝分派、事实或版本改变后原批准失效、重复请求不会重复分派，并可读回实际状态。网页保存 15 次 HTTP 请求的响应快照，线上可以逐步回放。

**客户、材料与公司规则是虚构的；本地程序是我们新增的，并非上游已有功能。** Claude 的真实请求因认证过期失败，没有成功执行插件或完成模型效果对比。案例说明与证据见 [演示说明](demo/README.md)。

## 研究网页如何使用

从 [在线研究网页](https://yydshly.github.io/1021_codex_project/projects/003-knowledge-work-plugins/) 开始，先看引导图，再按角色与场景查阅输入、流程、控制、异常、审批、验收和价值，最后编辑复制需求模板。线上部署为静态页面；工单现场操作需按演示说明启动本地 Python 服务。

上游版本固定为 `a266ab8c3c754a3ccf7a634044fc1595fc06e50e`，原仓库为 [anthropics/knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins)，许可证 Apache-2.0。研究结论、适配建议与验证边界以 [研究记录](notes.md) 为准。
