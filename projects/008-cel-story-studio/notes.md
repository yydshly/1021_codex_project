# 实践记录

日期：2026-10-20。

## 目标

用户选择以“逐帧手绘”为入口，第一版用于“故事表达：角色、动作和简短情节”。因此采用固定三幕的可编辑故事模板，完成编辑、预览和导出的闭环，不以任意故事自动生成作为本轮验收目标。

## 复用与新增

复用 mg-styles-15 固定版本中的 Canvas2D 绘线引擎及纸纹。引擎通过中心线、压力变化和噪声生成粗细变化的笔触，并使填色与轮廓略微错位。引入的两项资源均校验 Git blob SHA-1，索引见 `app/source-index.json`。

新增三种角色、三幕故事、帧驱动运动、文案适配、三组配色、两种越障动作、编辑工作台、本机渲染服务和确定性合成音轨。未直接复用上游完整 `scene.js` 或原片音轨。

## 质量修正

- 初始标题出现最后一个字单独换行，改为在适合的位置优先按中文标点断行。
- 初始跳跃弧线过高，可能与顶部文案重叠；调整角色尺度、弧线和标题安全区。
- 初次导出尝试下载 Headless Shell；改为优先复用已安装的 Chrome / Edge，保留手动路径与自动下载回退。
- 画面必须等字体和纸纹加载完毕、首次 Canvas 绘制完成后，才放行 Remotion 渲染。

## 验证结果

- TypeScript 类型检查通过。
- 输入约束的 5 项测试通过，覆盖正常配置、空白与超长文字、非法选项、错误类型、非法数值，以及额外字段过滤。
- 网页按钮实际发起两次有效导出：默认火苗故事有 AAC 音轨；自定义标题的小水滴故事关闭声音后没有音轨。
- 默认电影 1280×720、24 fps、288 视频帧，H.264 / AAC，完整解码通过。
- 关键帧见 `assets/frame-01.png`、`assets/frame-02.png`、`assets/frame-03.png`；修改后的输出见 `assets/variant.png`。
- 编辑、分镜跳转、播放、配置导出与导入通过浏览器操作验证。390 px 手机断点无横向溢出。

局限：目前没有自由故事理解、任意角色上传、旁白、竖屏和多时长能力；没有做长时间并发渲染压力测试。听觉响度未按广播交付规范进行 LUFS 验收，不复用上游提示词中的商业质量评分。

## 2026-10-21：可编排故事板（0.2.0）

### 实现

将 `opening/challenge/ending/motion` 固定字段升级为 `schemaVersion: 2` 与 `shots[]`。每镜独立保存稳定 ID、动作、情绪、字幕和时长，支持 1–10 镜、每镜 1–6 秒半秒步进。原三幕配置可迁移为 12 秒的三个镜头；旧配置在升级前已通过网页下载，并备份至被忽略的 `app/.cache/pre-storyboard-story.json`。

新增纯函数时间轴编译器。角色从左侧开始；逐镜计算开始／结束位置与星光状态。重排后重新累计前缀，因此删掉退缩镜头会改变后面跳跃的起点；失败回落后，下一镜从失败后的落点出发。所有动作末帧回到稳定姿态，常规运动保留手绘抽帧节奏。情绪改变眉眼、嘴型、姿态、抖动和局部符号。五种表情独立于七种动作选择。

Remotion `calculateMetadata` 使用同一时间轴确定成片长度。音乐改为 8 秒循环床，动作音效按镜头时间定位；长度变化不再沿用旧版固定 12 秒音轨。全局标题和结尾短句保留，画面采用一个连续舞台。

### 导出故障与修正

最初 Chrome 成功导出 12 秒、13 秒两个故事。最终复验出现 `waiting for the page to render the React component failed: timeout 33000ms exceeded`，随后单进程仍在读取 Composition 时超时。当时可用物理内存不足 500 MB，这只是环境观测，未证明是唯一原因。相同 bundle 使用本机 Edge 可以在约 3.5 秒内读出 288 帧、24 fps。

服务改为 Windows 优先选用已安装的 Edge，Chrome 为备用，仍允许 `CHROME_PATH` 显式覆盖；渲染并行数降为 1。不更改或结束用户现有浏览器进程。最终媒体结果由 `scripts/verify.py` 核对并写入 `assets/verification.json`，避免以网页“任务完成”单独代替视频验收。

### 本轮边界

支持的是有限动作故事板：单角色、固定舞台、固定星星目标。还没有自由故事理解、任意图片角色、多角色互动、摄像机调度、通用碰撞、旁白或竖屏。情绪切镜直接切换，不插值表情。最长 60 秒配置通过边界逻辑测试，未将所有 60 秒组合逐个导出。音频未做广播级 LUFS 验收。

## 2026-10-21：AI 故事导演（0.3.0）

### 用户故事与实现

用户期望由 AI 创意生成故事，自动驱动后面的分镜和画面。本轮完成：故事种子（可留空）／改写要求 → 真实模型生成完整故事与结构化镜头 → 参数校验与配时 → 工作台预览 → 可选自动渲染 MP4。

发现本机已安装并登录 Codex CLI `0.163.0`，环境中没有可用的通用模型 API Key，因此选择现有 Codex 登录作为第一版连接方式。使用 OpenAI 官方文档和本机 `codex exec --help` 验证非交互、临时会话、只读运行、输出 Schema 与最后消息文件等参数。没有复制、输出或存储登录凭据；模型服务需要网络与当前 Codex 账户可用额度，不是离线本地模型。本版没有新增 AI SDK 或通用 API 供应商依赖。

AI 编写标题、完整故事、概括、结尾短句，以及每镜动作、情绪、字幕和时长。严格限定一个舞台、一名角色与当前动作集合，创意落在动机、尝试、失败、退缩、重试和情绪转折上。服务端分配唯一镜头 ID，过滤额外字段；不合法的动作、情绪、文字、数量和主角会被拒绝，最多请求一次修正。仅对合法镜头调整半秒节奏，使合计精确达到 12／20／30 秒。

创作内容通过标准输入发送，不拼接到 shell 命令；生成运行不加载用户配置，禁用 shell、浏览器、多代理、插件和 hooks，使用只读临时会话。生成结果只作为 JSON 数据进入现有 Canvas／Remotion 引擎，不执行模型给出的代码。一次只允许一个 AI 创作任务，支持取消、超时退出和有限修正；错误不会用固定模板替代。

### 网页与接口

- 顶部 AI 表单支持新创作、改写、三种故事气质、AI 自选或指定主角、三种目标时长，以及生成后直接导出。
- 生成完成自动填入故事板与预览，仍可手工改镜头。原稿可展开，提供跳到画面与分镜的入口。
- 生成期间如果手动改了故事，结果只进入待采用草稿。明确采用后才替换并按选择导出。
- 支持取消、恢复最近一次生成前版本、在配置 JSON 中保存／回读 `creative` 原稿元数据。
- API：`GET /api/ai/status`、`POST /api/ai/generate`、`GET /api/ai/jobs/:id`、`POST /api/ai/jobs/:id/cancel`。任务状态仅保存在当前服务进程中；跨重启请保存 JSON。
- 校正了请求体分块 UTF-8 解码，避免中文字符被网络分块拆断。请求体限制为 32 KiB，并保留本机同源保护。

## 2026-10-21：十五种风格的创作雏形（0.4.0）

### 目标与范围

按照“先做雏形、补全剩余效果”的要求，在 008 现有工作台里增加其余十四种视觉绘制器，共十五种。不是重新搭十五个平台，也没有将上游十五段成片当作模板播放。共用 AI 创作、结构化故事、镜头增删重排、动作情绪、预览、配置和导出；各风格提供自己的构图、轮廓与材料处理。

风格包括扁平矢量、线条、等轴、3D 质感、手绘、拼贴、液态、形变、包豪斯、霓虹、极光玻璃、花字、贴纸、像素与 HUD。目录逐项展示原理、价值、适用场景、实现、目前边界、扩展和固定版本的上游路径。

### 技术落地

- `scripts/styles.mjs` 为统一风格目录。配置沿用 schemaVersion 2，新增白名单 `style`；旧版缺省手绘，显式非法风格拒绝，未知外部路径继续过滤。
- AI 请求携带风格，提示词说明视觉语言和有限舞台；接受结果时保留用户选择，模型不能偷换风格。没有新增模型供应商或凭据。
- `src/visuals.ts` 按风格分发绘制。所有效果由帧号确定，预览与导出共用同一 Composition。手绘引擎及纸纹来源 SHA 未改变。
- 特殊实现：等轴使用平行投影挤出面，液态采样平滑 SDF，形变使用 80 点对应轮廓，像素使用 320×180 最近邻放大，花字按字延迟弹性出现，HUD 显示实际动作、情绪与位置。
- 风格卡片为本项目实际生成的 480×270 代表帧；每种保留 3 秒 H.264/AAC 样片。45 秒连播为这些样片的标准 24 fps 合成，约 3.6 MB，MP4 faststart；网页 `preload=none`，展开并播放后才加载。
- 播放器旁增加独立下拉切换器，方便停在同一帧比较。切换暂停预览、保留故事和进度，载入预设也保留风格。呼吸感明确仅用于手绘。

### 明确边界

这是一组视觉原型，不是原片逐镜复刻。3D 质感为 Canvas 光照渐变和软阴影，不是三维模型／Cycles；玻璃没有真实折射；液态不是物理流体；拼贴尚无照片资产；像素字幕暂用清晰中文字体。单角色、固定小山与星星目标、七动作和五情绪仍是共同故事边界。精细画质、题材扩展与特定行业模板需要后续分批制作。

## 2026-10-21：AI 故事世界（0.5.0）

### 用户需求与架构

用户指出十五种风格仍共享同一个角色和舞台，期望角色、场景和行动随故事生成。本轮将经典舞台保留为 V1／V2 兼容入口，新增 V3 世界数据：角色与道具的矢量形状、独立场景布景、每镜出镜者和交互引用，以及自定义表演关键帧。

AI 输出角色、环境和物件的具体几何、颜色和部件，而非从火苗／水滴／星星或预设物种中选择。角色资产跨镜复用保持形象一致。基础形状限制为椭圆、矩形、多边形和线，资源和坐标受限；不执行模型返回代码。没有新增图像／视频模型接口或外部位图素材。

时间轴编译角色落点、场景切换与物件持有状态；拿起、递交、放下及推动改变物件状态，携带可以跨镜头与换场。缺少道具、尚未持有、距离过远或接收者不在镜头内会拒绝导出。手改期间预览仍能显示已有有效内容和参数错误。

十六类基础行为外，新增 `perform`：2–8 个关键帧控制身体偏移、旋转、左右臂、头部和物件倾角，可组合水流、生长、闪光、蒸汽。水流发射位置参考道具外形，持物高度随自定义右臂角度变化；这些是通用近似，尚无精细手部接触或通用物理。
