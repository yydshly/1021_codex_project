THE VALUE / 核心价值

实时水流模拟，
与水面效果的完整实现。

它的主要价值是把水深与流速的实时模拟和反射、折射、泡沫、飞溅等水面效果接成一套可运行的浏览器实现。

对我们而言，值得沉淀的是可复用的水流内核、材质与 GPU 数据组织方式，为三维自然场景、互动展陈、游戏浅水水体与原理教学提供基础。当前研究未发现新水流算法的证据；它的价值主要在实现与整合。

01 / 生成河床

先有河床，水才知道往哪走。

根据固定种子与区段位置，生成河床、岩石和植被。岩石的可见形状与水流障碍共用几何函数，让看到的石头与参与计算的石头保持一致。

种子 + 河段位置 → 可重复生成的地形

查看 river.cu 源码 ↗
实际执行路径.cu 源码→CUDA WebShader→WGSL / WebGPU→Three.js 画面

无需 CUDA Toolkit；计算最终运行在浏览器 WebGPU。模拟与绘制共享 GPU 缓冲区。

193 × 441每河段模拟网格

以上为研究版本中的配置，不是本机性能测量；模拟更新频率不等于画面帧率。

01 / 优先尝试

水面材质

反射 · 折射 · 流动纹理

可以沉淀什么

提取深度相关颜色、菲涅耳反射、折射与随流速移动的细节公式，整理成可调节的水面材质模板。

materials.js ↗

接入时需要什么

适配水深、法线、流速、泡沫、噪声纹理及场景深度等输入。可以先迁移材质思路；独立于原求解器使用的效果仍需验证。

02 / 增强接触感

泡沫、湿岩与飞溅

流动驱动 · 生成与衰减

可以沉淀什么

把泡沫生成与输运、岩石湿润及干燥、粒子出生与寿命组织成可复用的水体接触效果。

impacts.cu ↗river.cu ↗

接入时需要什么

用实际湿流、速度和碰撞区域触发效果，适配发射位置与生命周期。不能只把粒子贴上去，就视为完成水流交互。

03 / 按交互需要引入

浅水模拟内核

水深 · 流速 · 通量 · 边界

可以沉淀什么

提取网格状态、速度更新、通量限制、水深积分和泡沫输运，实现会响应地形与障碍的浅水流动。

coastal-kernels.cu ↗

接入时需要什么

重新配置河床、障碍、进出水边界、网格分辨率和步长，并重做稳定性与体积检查。完整三维翻卷浪不在该模型范围内。

04 / 支撑持续运行

GPU 与场景管线

共享缓冲 · 固定步长 · 区段复用

可以沉淀什么

复用计算与绘制共享数据的方式、固定步长调度、分批初始化，以及种子生成和区段资源池的组织方法。

solver.js ↗sections.js ↗

接入时需要什么

适配 WebGPU 设备、缓冲布局和渲染器接口。分段世界适用于长距离探索；较小展示场景可先保留单段，减少集成复杂度。

对我们的意义

积累可调整的水体能力，
减少下一次从零实现与联调。

面向三维自然场景、互动展示与游戏水体，沉淀材质模板、效果组件、求解器接口和 GPU 数据契约。性能与开发成本收益需要在目标项目中验证。

建议顺序：先复用材质与接触效果 → 有地形交互需求再接入模拟 → 长距离场景再引入分段加载。

把计算过程变成可观察内容

在网格和通量基础上增加水深、速度矢量与流入流出显示，辅助讲解算法。教学可视化需另行开发，不作为工程水文预测。

已有成果：原版实机运行、能力说明与源码定位。待完成：模块提取、独立接口、参数预设、跨项目接入与测试。复制代码时需保留上游及组件许可证。

CAPABILITY & LIMITS

看起来是三维，
求解的是浅水高度场。

它擅长把河床上的流动变成可以实时观察的画面。理解模型边界，比只看逼真程度更重要。

适合研究

实时水流与浏览器图形

学习浅水求解、GPU 数据共享、水面材质、粒子效果与分段场景管理。

模型边界

不完整求解翻卷浪和悬空水片

每个水平位置主要对应一个水面高度。瀑布沿陡峭河床坡面流动，飞溅属于受流动驱动的视觉粒子。

状态与兼容性

远处动态状态不会永久保存

被回收的河段回来时会重新生成；跨河段连接不是全世界统一的严格守恒求解。原版没有 WebGL / CPU 回退。
