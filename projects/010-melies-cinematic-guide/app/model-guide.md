# 将镜头库用作模型的创作参考

本研究于2026-10-22按用户要求暂时归档，后期围绕具体需求重启。先读 `archive-summary.json` 的定位、五类问题、16项动作／表达观察、证据边界与重启步骤，再检索相关案例。它是一份创作的动作素材与电影语言参考库：情绪需要决定情境和动作，语言模型选择参考并设计提示词，视频模型生成，实际复核后经验回库。424项不等于424个已验证人物动作。

`publicationSummary` 分别列出现有能力、可沉淀技术和后续使用场景。当前可复用的是动作与状态描述、索引与案例结构、分镜与提示词交接、输入／参考／素材追溯及审片方法。自动物理判断、语义检索与模型编排尚未实现；品牌服务、产品工艺、人物叙事和团队创作助手是后续按需扩展方向，不能写成已经交付的通用工具。

归档补充复核确认取车第三／四镜座垫差异在静态参考中已经存在；动作次数、起步与接触要求也有未落实的执行偏差。此前“基本可读”不等于物体结构和整片可信度已合格，助手参考制作与验收有责任。任务过密、参考方式等仅是未隔离的可能因素；不分配提示词与模型的责任百分比，不保证改词或换模型就解决。历史设计、原始执行与候选状态保留，后续补充见 `bike-kindness.archiveReview`。

重启时先统一资产，再拆分单一主要动作、固定输入做小样对照；候选与未来扩展均尚未实现。当前归档不授权继续付费生成，旧批次批准不可用于新任务。

这份库提供电影语言的参考规则、原站效果与双语例子。模型需要围绕新的创作目标做取舍、设计和改写；库中的例子不是必须照抄的剧情，也不是执行运镜的控制 API。

## 情绪与动作的主创作入口

网页 `#direct` 采用“输入目标 → 当前助手比较创作方向 → 设计情境与动作 → 选参考与设计镜头 → 导入双语方案 → 制作后记录反馈”。用户只需先填写创作目的与希望留下的感受，主体、场景等未指定条件由助手提出明确假设。网页不做在线模型推理，也不将情绪与运镜按关键词固定配对。

### 新稿的三层创作结构

新方案采用 `schemaVersion: 3`、`kind: creative_direction_pipeline`；原第2版稿继续导入，不给历史补写上层判断。第3版继续使用原逐镜双语字段与情绪／动作检查，并增加：

1. `creativeDirection`：面向谁、观看用途、表达命题、期待回应、明确假设，比较2–6个方向候选，选择其中一个并说明取舍、可观察目标与误读风险。不要只列“温暖／高级／电影感”。
2. `situation`：人物、何时何地、初始处境、动机、触发事件、行动结果与连续性规则。`causalChain` 按每镜顺序写 `{shotId,event,change,meaning}`，说明什么事引发什么行动、改变什么关系。地点不是完整情境。
3. `referenceSelection`：`selected` 每条为 `{type:case或technique,id,reason,transfer,adapt,boundary}`；案例集合与 `provenance.referenceCaseIds` 一致，技巧集合与逐镜 `references` 合集一致。`rejected` 至少说明一个未选真实参考及原因；`gaps` 写无现成经验的部分。允许没有合适选中参考，不硬套案例。

按目标检索索引，读取少量完整记录再创作。模型任务含四个案例的经验摘要、最新返修摘要和原始证据边界，完整记录仍需读取。制作后重新判断内容与动作、表达线索与观众感受，不能因引用真实案例就继承其效果。

新题材[《有人，帮你一把》](pipeline-example.json)为20秒社区取车设计：从三个方向中选择“日常被照应”，通过注意来人、擦干座垫、扶稳交接与继续推车，把情境意义落实为动作。参考旧书交还和陶器状态检查，采用双人镜头、插入细节和后方跟拍；舍弃后拉停留和眼部大特写。`framing-insert` 的原提示词疑似错配，本设计只借其定义。原稿保留设计阶段状态；实际四镜、20秒成片与复盘以第四个案例 `bike-kindness` 独立记录，准确输入与五张参考见bike-kindness-plan.json和bike-reference-prompts.json。已经做画面复核，未听评音轨，无观众反馈。[完整选中参考与设计](pipeline-reference-bundle.json)保留当时选择，不用本案生成结果伪造原设计依据。

- “复制情绪与动作创作任务”带全部424项轻量索引与当前四个实际题材的索引和边界。当前助手自行选取少量相关项，并读取 `web/capabilities.json`、`web/case-library.json` 中相应完整记录；其他环境需另外附带完整资料。不能把索引或文字说明说成观看过原片。
- 先明确目标观众感受与情境意义。情绪可维持、加深或转折，分别用 `maintain`、`deepen`、`turn`；仅转折强制填写触发事件。不得把柔光、暖色、慢动作等固定等同于某种情绪。
- 原第2版 `emotion_action_direction` 与新第3版均使用：逐镜 `emotionalBeat` 写意图、可见事件、判断理由与可能的另一种解读；`action` 写开始、行动与回应、结束和接触／空间关系；`expression` 写机位运动、构图、光线、时间安排和声音。
- `references` 可以引用任意真实的 424 项 ID，每条说明 `purpose`、`retain`、`adapt`。允许无合适参考时不引用。7 项已提炼规则仍是子集，不声称其余 417 项已编译为执行规则。第 2 版机位用双语描述，不沿用旧试点只允许 fixed/arc-left 的限制；结构校验不判断自由文本冲突。
- `referencePlan` 写明当前尚需准备哪些身份、构图、动作首尾参考；`direction` 写具体、对应的双语表达要求。网页按双语设计字段整理提示词，不自动翻译；转场与后期方法另外展示。
- 当前助手的陶器设计示例 `app/direction-example.json` 为 15 秒、3 镜，选用微距、后方跟拍与后拉。原设计保持design_only；实际15秒视频与复盘以tea-moment独立入库，尚无观众反馈。原旧书设计与首版／返修证据保持历史状态。
- 陶器现在另有三张实际生成的静态关键画面，制作记录为 `tea-moment-keyframes.json`（网页目录）。模型可读取准确图片输入、参考角色、静态观察、问题与复用笔记；这是静态制作记录，不是视频案例。初稿把蓝点画到杯身正面，定向修改后移除；近景显示把手下连接处的单点，中远景受遮挡，不能证明全程一致。另做宽景终态以区别房间身份参考和后拉终态；这是当时的静态制作记录；实际视频另读tea-moment案例，不用视频结果改写这份历史。原分镜的历史状态及当时“尚无素材”说明保留，新参考在制作记录里说明。
- 每镜的 `checks.action` 与 `checks.expression` 是检查计划。实际制作后分别记录动作关系、表达线索、观看依据、观众自身感受与差距；模型观察与观众反馈分开。网页反馈只保存为本机 `user_reported_not_verified` 草稿，绑定完整设计快照，可追加、撤回／恢复和下载。下载交给助手核对原片与准确执行记录后，再按既有经验源记录入库；不自动升级验证状态。
- 新入口源码为 `direction-engine.js`、`direction.js`、`direction-panel.html`、`direction.css`。空白结构由网页下载。原 `#studio` 和第 1 版分镜继续工作；不要修改原设计来伪造逐镜情绪判断的历史。

## 可读取的资料

- `technique-rules.json`：首批 7 项结构化规则，含核心要求、候选用途、参数、适用条件、检查标准、来源摘句与原文哈希，以及单次香水经验关联。用途属于设计归纳；示例角度、空白比例不代表实测能力。
- `studio-book-repair.json`：助手原创的《让故事，继续》原始分镜，18 秒、4 镜，选用微距、体积光与留白。保留设计阶段的 `design_only` 与当时证据说明；本次实际素材和偏差另存于 `case-library.json` 的 `book-repair`，不回写伪造原设计历史。

- `capability-index.json`：424 项简明索引。先从目标和情绪寻找候选能力。
- `capabilities.json`：完整能力记录，含来源、规则说明、双语原例和素材链接。按候选 ID 读取相关条目，避免把 424 条全部堆入一次生成请求。
- `creative-case.json`：本次原创分镜案例，展示规则如何变成新故事。
- `case-index.json`：创作经验的简明索引，按目标、情绪、标签、模型或技巧 ID 选择案例。目前有香水、旧书、陶器、社区取车四个题材，各一套首版执行；旧书另有一次两镜局部返修，以 `revisionCount` 和 `revisionSummary` 检索，不代表通用成功率。
- `case-library.json`：完整经验记录，包含创作目标、选镜理由、真实输入、实际效果、问题、可迁移思路及未验证的候选改法。素材路径相对于该文件所在网页目录。

技巧索引和完整能力记录中的 `experienceRefs` 指向使用过该技巧的案例和分镜。它表示存在可查看的经验，不表示该技巧已严格达标；原站的 `reviewNotes` 仍只记录原站来源疑点。

## 建议给模型的任务指令

你是一名创意导演与提示词设计师。请将附带的能力库作为电影语言参考，围绕用户的创作简报设计原创方案。

1. 从简报提炼目标、受众、情绪变化、主要对象、时长、画幅和交付形式。缺少的非关键条件可给出明确的设计假设；涉及关键选择时说明假设。
2. 先提出有主题的创意，再从库中挑选相关技巧。说明每项如何服务叙事，避免只是把多个术语串起来。
3. 检查所选条目的 `reviewNotes`。有疑似来源错配时，使用已说明的技巧规则并明确复核，不把错误原例直接作为创作依据。
4. 保留技巧的运动、空间或剪辑规则，改写人物、产品、场景、视觉母题、节奏和叙事。将“借用规则”与“本次新增设计”分开写。
5. 单个镜头明确一个主要运动。灯光、景深和材质可以配合，但不要让主体自转、相机环绕、变焦与焦点转移无理由地同时发生。
6. 先定义跨镜头的外观、场景、光向和色彩锚点，再逐镜写中文与英文提示词。两种语言表达同一设计；每段提示词应能独立复制使用。
7. 转场交代切点两侧的形状、位置、方向和时序；复杂剪辑分别生成片段后完成。时长为目标剪辑时长，具体模型支持的时长需另行核对。
8. 对新增设计给出依据，引用真实能力 ID 与来源 URL。可以提出库外的新组合或表达，但不得虚构库中存在的能力或证据。
9. 读取相关案例经验后，输出目标、概念、统一锚点、分镜、引用规则、原创增量、中英文提示词、剪辑方式和待验证事项。说明复用了哪个案例、哪些逻辑、哪些内容是新设计。
10. 未实际调用模型或观看结果时，只称为设计方案。原站示例不能用来证明本次方案已经生成或可以被任意模型稳定复现。

### 先检查内容与动作逻辑

镜头技巧不能代替物体结构与动作因果。逐镜先明确对象数量、动作作用位置、固定部分、连接轴、施力与移动方向、动作前后状态，以及跨镜朝向是否连续；再判断景别、光线和叙事表达。写入 `reason` 与 `checks`，但网页结构校验不会自动证明这些关系正确。

旧书首版复核中，`book-2` 的针落点没有对应本方案的书脊既有装订孔，且有疑似叠书；`book-3` 的封面开合方向与可见书脊连接轴关系矛盾，不能只写成手部接触不清楚。两镜历史 `logicReview.assessment` 保留 `not_passed` 及对应时间的证据。新的 `revisions[0]`（`book-repair-r2`）实际重做这两镜：专用首尾图明确中缝孔与同一左侧长书脊，并缩小动作范围。实际入口位置、单一书体和小角度合书方向改善；出针侧、完整拉线及大幅开合没有验证。不得把它写成首版已经正确或完整工艺已通过。

## 复用方式

### 网页试点：当前助手创作，复制与导入

1. 在网页 `#studio` 输入创作简报。网页只用本地关键词提出候选，不调用语义模型；排除项不计正向分数，人工核对所有取舍。可以不选规则。
2. 复制“模型创作包”，交给当前助手。创作包带当前简报、选中规则与来源、相关单次经验、空白输出结构和填写约束。
3. 助手设计主题、情绪变化、动作事件、技巧取舍和双语字段，返回纯 JSON。`brief` 原样保留；模型可删减候选，但不能编造规则 ID。可参考旧书稿的结构，不能把它当成任意简报的返回模板。
4. 将 JSON 粘贴或导入网页。网页校验简报一致性、引用、双语必填项、时长、显式运动与参数、图形匹配配对，再将设计字段整理为逐镜中英文提示词。它不自动翻译，也不判断自由文本的所有语义冲突。
5. 两种语言可分别复制，完整创作包可下载 JSON（保留 `storyboard` 可再次导入），提示词可下载 Markdown。改变简报、选择或输入稿会使旧结果失效，重新校验后才输出。

试点支持固定机位基线，以及规则中的左弧线环绕；并非已经将其余 417 项编译成执行规则。规则不足时说明局限并扩展资料，不把不相关技巧硬套给新题材。生成工具、参考图、音轨、片长和后期排字需要在实际制作时另定。规则结构、分镜结构和模型写作说明详见 `app/workflow-engine.js` 的 `creativePackage` / `skeleton`。

旧书原设计从“修复并交还”出发：拟用微距看清材料与一次穿线，少量纸尘使窗光可见，末镜交还并留出片名空间；不用雨景、镜面、圆形匹配或环绕。实际生成后发现两镜未达微距尺度、穿针出现疑似叠书和孔位偏差、合书接触不连续可读、右侧留白未实现。交还动作与袖口角色区分可读，片名在后期改放实际空出的右上墙面。设计成立与实际执行达标必须分开判断。

规则的 `caseFeedback` 已关联相关题材的实际观察、问题、候选改法及局部返修；复制模型创作包会带上所选规则的这些反馈。模型可以引用真实提供的 `book-repair`、其 `book-repair-r2` 返修或 `rain-to-forest`，不可编造案例。引用局部返修时，`referenceCaseIds` 仍填父案例 `book-repair`，返修 ID 写入 `evidence`，不当作第三个题材。有 `revisions` 时先读最新实际观察与边界，再读首版历史；首版 `nextAttempt` 保留当时的未生成语义。本次首尾参考、景别、动作范围和文字一起改变，只能判断本段可见改善，不能归因于单一方法或保证跨题材复现。

### 检索完整资料

在本项目中，模型可以直接读取 `app/data.js` 或导出的 JSON；其他模型可附带这份指引、简明索引及选中能力记录。这样复用的是可解释的创作知识与工作流程，不需要把每个新题目都限制在固定模板里。

建议读取顺序：

1. 写清新简报的对象、目标、情绪、时长、画幅与已有素材。
2. 在 `capability-index.json` 与 `case-index.json` 中按语义、标签或技巧 ID 找候选；再读相关完整能力记录与案例。
3. 分别读取案例的 `goal`、`shotReviews.selectionReason`、`observedEffect`、`problems` 和 `review.limits`。本次效果部分符合设计时，保留这一状态。
4. 复用合适的 `reusePatterns`，改写主体、意象、场景与节奏。首版 `nextAttempt` 为历史候选；同时读取 `revisions` 的实际输入、结果、残留问题和 `lessons`，不能将旧状态混成新结论。
5. 输出新方案时，分别列出参考依据、改写内容、风险与验收方法。无法观看素材时，说明仅依据文字记录，不能声称已经观看。
6. 新生成后另记一次执行与实际观察，再评价改法是否有效；没有新的生成证据时，不增加样本数或升级验证状态。

### 社区取车的复用判断

读取 `bike-kindness` 时同时看14张带时间的证据帧与四镜原片，再决定哪些逻辑适合新目标。一套四镜首版只计一个样本：

- 关怀先落实为具体事件与回应，再以光线和节奏加强。此次擦干座垫与交接有照料线索，但开场已经平静，疲惫到安心的转折较弱。新目标需要情绪转折时，先设计可见起点。
- 把接触、握稳、承重、释放分开。此次先接触再松手基本可读，女方握稳程度与承重时刻未完全明确；不把手搭上物体写成严格物理验收通过。
