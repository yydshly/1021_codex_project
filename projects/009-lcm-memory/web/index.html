这个模块说明什么

AI 的记忆存放在模型外部，由宿主工具接入。

Hooks 随事件自动运行；MCP / CLI 允许 AI 主动查询和存储。两条路径都连接到同一个记忆后端，后端负责真正的数据与检索工作。

阅读时注意

当前上下文只是模型本轮能直接读取的材料，数据库保存更多历史。保存了内容、检索到了内容和正确使用了内容，需要分别判断。

文字版：把整张图连起来读 +
  1. 本质：LCM 是位于模型外部的项目记忆运行时，保存捕获的交互记录与整理后的知识。
  2. 交互：宿主 Hooks 在会话事件自动触发存取；AI 经 MCP 或 CLI 主动调用搜索、展开和保存。
  3. 存储：本地 SQLite 按项目、会话保存消息、结构化片段、摘要关系、当前上下文引用和长期条目。
  4. 整理：配置的模型生成分层摘要；正常压缩替换上下文引用，保留来源。长期条目来自摘要规则、事件处理或主动保存。
  5. 取回：启动恢复、问题自动提示、AI 主动追查是三条不同路径。文本检索、排序、去重和预算共同决定返回片段。
  6. 使用：相关材料作为附加上下文或工具结果返回模型，AI 判断是否需要查证、采用和更新。
  7. 场景：持续研究、长周期排错、决策追溯和受支持客户端之间的项目接续。
  8. 意义：预期减少重复说明与排查，保留经验和依据，维持跨会话连续性；收益需要真实任务验证。
  9. 条件：捕获可用、召回相关、依据有效、模型正确使用。摘要、旧结论、中文查询、隐私、成本和平台接入都有实际边界。

长期记忆如何入选？

摘要提升主要使用规则判断，符合条件的摘要正文进入 promoted 表。

①

摘要提升

命中决策 / 修复关键词、架构模式、深度 ≥ 2，或压缩比 < 0.3，任一信号即可成为候选。

②

事件提取

按规则处理决策、计划与操作模式。弱模式需要重复证据或已有记忆匹配，不是每条事件都长期保存。

③

主动保存

AI 或用户通过 store 明确写入结论，包含内容、标签、来源会话等元数据。

筛选分数 ≠ 事实正确率

摘要提升的 confidence 来自命中信号数量。相似内容按 BM25 匹配去重、合并标签并归档，不能据此认定系统已经解决新旧结论冲突。

筛选实现 ↗去重实现 ↗

下面的评分演示对应 B 路径，不能直接代表 A 的启动恢复或 C 的主动查询。

  1. 01处理当前问题

    拆词、去重、去虚词。自动路径不先让模型理解整段对话或消解指代。

  2. 02搜索两类记录

    长期条目查 promoted；历史层查消息和摘要。是否补充历史由客户端参数控制。

  3. 03排序与筛选

    长期提示考虑匹配、新鲜度、会话和反馈；历史层按会话融合原文与摘要排名。

  4. 04按预算注入

    先放合格长期条目，再补历史。默认最多 3 条提示，片段约 200 字符，另受字节预算限制。

INTERACTIVE EXPLAINER

同样匹配，为什么旧记忆可能排在后面？

教学示意 · 非真实召回测试

问题：“SQLite 并发写入失败，上次怎么解决？”
候选和匹配分为人工设定；计算采用源码的长期记忆基础评分与使用加成公式。此处不模拟冷却、陈旧惩罚或最终字节裁剪。

匹配分 × 0.5年龄 / 24 小时 × 会话权重 × 使用加成
长期记忆候选得分，随控件变化更新
候选记忆匹配分（假设）年龄 / 会话示例得分阈值判断

默认提示门槛：2跨会话权重：0.85使用加成：1 + 0.75 × n / (n + 1)

历史检索不套同一个公式

消息与摘要分别检索，按会话融合名次并控制结果分布。启用历史补充时，它排在筛选后的长期提示之后，共用输出预算。

主动查询不套自动提示的衰减

lcm_search 默认同时查历史与长期记忆。AI 可以改写关键词、提供跨语言查询，再用 expand 查证原文；旧记忆仍可能被找回。

自动提示评分 ↗历史融合检索 ↗主动查询 ↗

06 / FINDINGS & LIMITS

能查回历史，也需要判断历史。

存储完整性、检索命中和最终回答正确，是三件需要分别验证的事。

源码已确认

来源保留与按需展开

正常压缩保留原始消息及摘要关系。所谓“无损”的主要基础是来源可回溯，摘要本身仍可能遗漏细节。

机制有边界

检索依赖词汇重合

研究版本主要使用 FTS5 / BM25。模糊指代、同义改写和中文连续文本可能影响召回；当前路径不是向量语义检索。

尚未实测

项目上的实际收益

未安装 LCM，未验证捕获完整率、中文召回率、任务成功率、耗时、费用与跨客户端一致性。

既然 AI 已有记忆，为什么还需要 LCM？+

价值在于可检索的项目档案、来源追溯与受支持客户端共用后端。如果产品自带记忆已满足需求，额外系统的价值可能有限。

长期记忆过 180 天会被删除吗？+

不是。180 天是启动恢复长期记忆路径的默认年龄筛选条件。自动提示还有其他衰减和反馈规则；数据库保留、自动注入与主动检索是不同层面的行为。

是否每次都把全部历史重新发送给模型？+

不会。自动提示会截取片段、去重并限制条数与字节数。更多细节需要主动查询。Codex 的原生压缩继续运行，LCM 提供补充记忆。

“本地存储”是否意味着内容永不离开电脑？+

数据库保存在本地；如果配置外部摘要模型，处理后的内容仍会发给对应提供商。源码有脱敏流程，但本研究没有独立验证脱敏覆盖率。

仓库里的实验数据能证明它提升了编程成功率吗？+

不能直接这样推断。检索延迟、前五命中数、摘要事实保留和最终编程成功率是不同指标。上游有局部实验与评测框架，我们没有复现实验，也不把它们当作本项目效果保证。

下一步应验证

用真实中文研究会话，检查捕获是否完整 → 新会话能否找回 → 新旧决策能否区分 → AI 是否引用正确依据。

07 / HOW TO VERIFY

要判断有没有用，先设计能核对答案的问题。

下面是待执行的验证方案，不是已经完成的实验结果。建议在独立测试项目中使用可公开的样例记录。

一组可复核的对照

固定同一客户端和模型，准备相同任务与历史，分别在启用 / 未启用 LCM 的条件下运行；保存实际输入、检索结果、答案与工具记录。多次执行后再比较，避免把一次成功当作稳定收益。

五项需要分别验证的能力
验证点怎样设计看什么证据当前状态
捕获完整性在同一会话中留下唯一标记、一次失败及一次修复。入库内容与会话原文对照；明确脱敏、过滤与缺失项。待实测
跨会话召回另开会话，直接问标记，再改写为自然语言问题。目标记录是否出现在结果中、来源是否正确、两种问法有何差异。待实测
压缩后的细节事先记录一个精确版本号或失败原因，再经历摘要压缩。自动上下文是否保留；展开来源能否恢复；不能只看摘要流畅度。待实测
新旧结论冲突先选方案 A，随后明确改为 B，并注明时间与原因。两个来源是否可查；最终答案是否识别替代关系，引用当前有效决定。待实测
成本与任务收益选取有验收标准的持续任务，重复做启用 / 未启用对照。总模型调用、token、费用、耗时、重复排查次数与最终任务质量。待实测

术语速查：这些词分别指什么？ +
Hooks

MCP
让 AI 客户端调用外部工具的接口协议；不负责替模型决定何时查询。

Promoted
