02 原库在计算什么？

从植物身份到屏幕像素

真正值得拆的，
是画面背后的数据流。

RealGrass 的重点是让大量植物的生成、运动和可见性处理留在 GPU。CPU 主要传入相机与参数，渲染器直接读取 GPU 缓冲。下面按固定版本源码解释；这不代表完成了全套上游回归测试。

种子化生成 / GPU COMPUTE

草叶有身份，草丛有结构。

按植株、分蘖与叶序生成形态，而不是把所有叶片完全随机撒在地上。世界种子让同一位置能够复现；滑块修改的是生长快照，未连续模拟植物生命过程。

C → WGSL → GPU

CUDA C 内核通过 cuda-webshader 编译为 WGSL，再交给浏览器 WebGPU 执行。运行者不需要安装原生 CUDA，也不限定使用 NVIDIA 显卡；实际支持取决于浏览器与 GPU。

04 看起来相似，能力并不相同

实现事实 / 尚未量化的结论
我们的理解 / 当前两个版本的对照

原库整体更自然，
复杂机制有可见的价值。

这次观察中，原库在植物形态与云层空间感上更接近自然景观。自研版实现了草地氛围和基本交互，但尚未复现这些层次。这里的“更真实”指视觉可信度和运动连续性；两套方案都采用近似模型，尚未证明严格的植物学或物理准确性。

01 / 植物结构

从草叶到一株草。

原库用植株、分蘖、叶序与成熟度组织变化，草丛更有结构。自研版主要分布简化叶片，形态重复更明显。

02 / 运动状态

风停了，运动仍有历史。

原库保存弯曲和速度，支持局部受力后的持续回弹。自研版由时间函数与当前笔刷计算位移，缺少逐叶运动历史；尚未做动力学拟合比较。

弹簧状态依据 ↗
03 / 云层空间

云是一团体积，也可以是一层图案。

原库对三维云密度做体积采样，有明显的厚度与自遮光。自研版投影二维噪声云，能做云影，但空间层次更薄。

天气实现依据 ↗

这次实践的意义：简单方案足以搭建草地效果展示；当目标转向自然写实、持续交互和大范围漫游时，原库的额外机制就有明确用途。视觉判断基于当前演示与源码阅读，不代表已完成定量保真度或性能评测。

自研版独立实现，无第三方运行依赖。目标是解释取舍，不宣称达到原库的完整功能或保真度。

如何公平比较？

分别运行两者，固定设备、浏览器、画布分辨率、视角和观察时长，再记录帧时间与 GPU 耗时。并排运行会竞争 GPU；原库跨域嵌入无法同步相机、控制参数或读取内部 FPS，因此本页只提供人工视觉对照。

天空可以独立选型

云也不必只有一种做法。

天空盒 / 云贴片

用于固定或远景天空。资源与美术控制直接，但形变和空间深度有限。

二维程序噪声

本页方案。可共享场计算云影，少量采样即可表达变化；缺少体积穿行。

三维体积步进

原库方案。沿视线积累密度与透射，能进入云层；成本随采样与分辨率增加。
